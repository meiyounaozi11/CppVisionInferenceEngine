# ONNX Runtime CPU Inference

Stage 2 adds a single-thread CPU inference boundary to `CppVisionCore` using
the official Microsoft ONNX Runtime C++ API.

## Dependency

- Release: ONNX Runtime v1.29.0
- Asset: `onnxruntime-win-x64-1.29.0.zip`
- Source: <https://github.com/microsoft/onnxruntime/releases/tag/v1.29.0>
- SHA256: `c9b4b7086b529ad814f428c1bad028e20a25d7dc0699836775faace4ab5b78b2`
- Runtime root: supplied through `ONNXRUNTIME_ROOT`; never hard-coded in the
  repository

The package is the Windows x64 CPU release. No CUDA, DirectML, or other GPU
execution provider is enabled in this stage.

## Boundary

```text
cv::Mat
   ↓
ImagePreprocessor
   ↓
ImageTensor (std::vector<float>, NCHW)
   ↓
InferenceEngine
   ↓
InferenceResult (copied output values)
```

`InferenceEngine` does not load images or depend on preprocessing behavior. It
receives a tensor value, validates rank/dimensions/data size, creates an
`Ort::Value`, runs the CPU session, and copies float tensor outputs into STL
values.

## Session and Ownership

`InferenceEngine` owns an `Ort::Env` and an `Ort::Session` with RAII. The
members are destroyed in reverse declaration order, so the session is released
before the environment. Session options explicitly select sequential execution
and one intra-op/inter-op thread for this single-thread stage.

The input `std::vector<float>` remains alive for the complete `Session::Run`
call. ONNX Runtime output values are copied before the temporary `Ort::Value`
objects leave scope, so `InferenceResult` has no dependency on runtime-owned
buffers.

## Metadata and Validation

Initialization records input/output names and shapes through the allocator-owned
name APIs, copying names into `std::string`. Runtime input shape validation
accepts dynamic model dimensions but rejects rank mismatches, incompatible
static dimensions, and data/shape size mismatches.

## Fixture and Tests

`tests/models/identity_nchw.onnx` is a 150-byte identity model generated by
`scripts/generate_identity_model.py` with the official `onnx` Python package.
It accepts `[1, 3, 2, 2]` float input and returns the same values. This fixture
only proves inference plumbing; it is not a production vision model. Its
SHA256 is `109b7873993f0e7a1e8c43836a7f869a2b0d56eb742c8414e665b3cebd7264d1`.

`InferenceEngineTests` covers invalid and valid model loading, metadata,
validation, deterministic repeated inference, output values/shapes,
Stage 1-to-Stage 2 ownership, and session recreation.

## Runtime Deployment

Set `ONNXRUNTIME_ROOT` before configuring the MSVC presets. CMake imports the
release `.lib`/`.dll` and copies `onnxruntime.dll` and
`onnxruntime_providers_shared.dll` next to the application and test binaries.
This keeps runtime discovery local to the executable directory and does not
modify the system PATH.
